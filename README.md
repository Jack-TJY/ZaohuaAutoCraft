# 自动炼丹炼器（ZaohuaAutoCraft）

《造化仙缘》的 BepInEx 插件：在炼丹界面选好丹方、在炼器界面选好符文，自动算出材料怎么摆进阴阳两边的格子，并替你摆上。炼制/锻造按钮仍由你自己点。

> 当前进度：炼丹 5 种模式（最少材料 / 最低品阶 / 最多成丹 / 最高品质 / 最多可炼次数）；炼器已改为**统一流程**（符文优先级组 + 可选成品属性 + 材料策略），不再按模式切换。精确求解用 CP-SAT（OR-Tools），紧盘/多材料配方自动切换「按形状类型联合建模」，分解路径失败才回退启发式。

## 安装

1. 游戏需已装好 BepInEx 5（x64）。
2. 把 `ZaohuaAutoCraft.dll` 放进 `游戏目录\BepInEx\plugins\`。
3. 进游戏打开炼丹界面，右上角会出现「自动摆放 (F8)」按钮。

## 使用

1. 装备好丹炉，打开炼丹界面，点「自动摆放」。
2. 在列表里选丹方（默认只列已学的丹方和自己炼过的配方；勾「显示全部丹方」可列出全部）。
3. 点「计算摆法」，确认材料清单后点「摆上」。
4. 插件会读取游戏自己的结算结果核对丹方是否识别正确，然后由你点「炼制」。

炼器：装备好锻造锤，打开炼器界面，按 `F10` 打开「自动炼器」窗口（炼丹是 `F9`），先在游戏原界面勾选符文，再点「计算摆法」→「摆上」。

配置文件 `BepInEx\config\zaohua.autocraft.cfg`：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| ShowAllRecipes | false | 是否列出全部丹方 |
| OpenKey | F9 | 打开/关闭窗口（F5/F8 是游戏的快速存读档） |
| Mode | MinPieces | 默认模式，窗口里切换会自动记住 |
| TimeLimitMs | 3000 | 最长计算时间（毫秒），用于最少材料/最低品阶/最多可炼次数/建议补料；一般 1 秒内算完，用满仍无解可调大 |
| PlacementTimeLimitMs | 8000 | 最长计算时间（毫秒），用于最多成丹/最高品质；时间越长丹数/品质越高，但要等这么久 |
| ButtonX / ButtonY | -1 | 「自动摆放」按钮位置，拖动按钮会自动改 |

两个时间上限也能在窗口里按 −/+ 直接调。「最多成丹」只给一个方案，其余模式最多给 3 个。

## 原理

- 游戏规则（反编译所得）：阳格加属性、阴格减属性，加上丹炉/天赋的固定加成后，必须与丹方要求**完全相等**才出丹。
- 选材：按件数从少到多逐层搜索；同属性的材料归为一类；用单维可达性表和势函数下界剪枝。
- 装箱：异形块回溯（每次覆盖第一个空格或在预算内留空），先做棋盘与按行列模 k 染色快筛。
- 摆放：调用游戏自带的 `CraftingDrugCell.LoadCraftingTemplateSto`，与「配方」页一键摆放走同一逻辑。

## 炼器统一流程

选定符文后，窗口里设置三件事：**符文优先级**（可多选、可调顺序，勾选=优先组）、**成品属性**（不指定/金水木火土冰风雷）、**材料策略**（最多炼制次数 / 低阶材料优先），点「计算摆法」。

求解流程（详细性能分析与优化记录见项目 issues / 提交历史）：

1. **分解模型**（数量 CP-SAT + 几何装填，占约 40% 预算）；数量解装不下时加形状切割重求；
2. 失败则切换 **联合几何模型**：材料按「旋转等价形状」归类，位置变量按类型而不是逐材料枚举（189 种材料只有 17 类形状，位置变量 40418 → 3702），几何与数量在同一模型里求解；
3. 联合模型分两阶段：**质量阶段**（优先级组 + 逐层覆盖 + 等级）→ **材料阶段**（固定质量后优化批次/低阶，用质量阶段方案热启动）；
4. 满级可行性通常 1 秒内出结论；满级不可行后按「覆盖数」逐层二分（`Σ hasL[r][l] >= H_l` 硬约束），每次 5~12 秒；
5. 紧盘输入（有效材料 > 80 且形状类型 ≤ 32）自动把预算从 30 秒放宽到 60 秒；
6. 所有候选都通过独立复核（库存、越界、重叠、符文层数、成品属性）才展示；相同输入直接复用上次已验证结果，不重复搜索。

### 实验性方案（默认关闭，仅保留代码）

- **180° 对称破坏**：联合模型支持对任意矩形盘加「前一半至少占一格」的约束。离线多尺寸测试（3×3~10×10）表明它**反而更慢或质量下降**（5×5 慢 3.4 倍，7×7 从 Optimal 降为 Feasible，7×10 覆盖从 50301 退到 50300），因此默认关闭。
- **确定性复现**：`EquipmentDeterministic`（默认关）锁定单线程 + 固定种子，仅调试用。

## 构建

`lib/` 下放以下 dll（不随仓库分发）：游戏 `Zaohua_Data\Managed` 里的 `Assembly-CSharp`、`UnityEngine`、`UnityEngine.CoreModule`、`UnityEngine.IMGUIModule`、`UnityEngine.InputLegacyModule`、`UnityEngine.TextRenderingModule`、`UnityEngine.UI`，以及 `BepInEx\core` 里的 `BepInEx`、`0Harmony`。

```
dotnet build src -c Release
```

离线测试（需先用 [zaohua-guixu-shop 的 tools/extract.py](https://github.com/Jack-TJY/zaohua-guixu-shop) 解出配置表）：

```
dotnet run --project tests -c Release -- unpacked/data
```

环境变量可开关的专项测试：

| 变量 | 作用 |
| --- | --- |
| `UTEST=1` | 炼器统一流程验收用例（覆盖优先/逐层覆盖/部分激活/优先级/上限差异/共享需求/未激活负属性/并列归金等） |
| `P1FIX=1` | 早期缺陷回归 |
| `SHOE=1` | 鞋子2 配方复现（真实库存 + 7×10） |
| `GRIDSET=1` | 多尺寸盘对比测试集（3×3 / 4×4 / 5×5 / 5×8 / 7×7 / 7×10 / 9×10 / 10×10，对比有/无对称破坏） |
