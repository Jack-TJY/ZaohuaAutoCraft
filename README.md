# 自动炼丹炼器（ZaohuaAutoCraft）

《造化仙缘》的 BepInEx 插件：在炼丹界面选好丹方、在炼器界面选好符文，自动算出材料怎么摆进阴阳两边的格子，并替你摆上。炼制/锻造按钮仍由你自己点。

> 当前进度：炼丹 5 种模式（最少材料 / 最低品阶 / 最多成丹 / 最高品质 / 最多可炼次数）；炼器已改为**统一流程**（符文优先级组 + 可选成品属性 + 材料策略），不再按模式切换。精确求解用 CP-SAT（OR-Tools），紧盘/多材料配方自动切换「按形状类型联合建模」，分解路径失败才回退启发式。

## 安装

1. 游戏需已装好 BepInEx 5（x64）。
2. 把 `ZaohuaAutoCraft.dll` 放进 `游戏目录\BepInEx\plugins\`。
3. 进游戏打开炼丹界面，右上角会出现「自动摆放 (F8)」按钮。

## 使用

1. 装备好丹炉，打开炼丹界面，点「自动摆放」。
2. 在列表里选丹方（默认只列已学的丹方和自己炼过的配方；勾「显示全部丹方」可列出全部）。
3. 点「计算摆法」，确认材料清单后点「摆上」。
4. 插件会读取游戏自己的结算结果核对丹方是否识别正确，然后由你点「炼制」。

炼器：装备好锻造锤，打开炼器界面，按 `F10` 打开「自动炼器」窗口（炼丹是 `F9`），先在游戏原界面勾选符文，再点「计算摆法」→「摆上」。

配置文件 `BepInEx\config\zaohua.autocraft.cfg`：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| ShowAllRecipes | false | 是否列出全部丹方 |
| OpenKey | F9 | 打开/关闭窗口（F5/F8 是游戏的快速存读档） |
| Mode | MinPieces | 默认模式，窗口里切换会自动记住 |
| TimeLimitMs | 3000 | 最长计算时间（毫秒），用于最少材料/最低品阶/最多可炼次数/建议补料；一般 1 秒内算完，用满仍无解可调大 |
| PlacementTimeLimitMs | 8000 | 最长计算时间（毫秒），用于最多成丹/最高品质；时间越长丹数/品质越高，但要等这么久 |
| ButtonX / ButtonY | -1 | 「自动摆放」按钮位置，拖动按钮会自动改 |

炼器段（`[炼器]`）：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| EquipmentTimeLimitMs | 3000 | 炼器最长计算时间（毫秒）。材料多/盘面紧时会自动放宽（见下），一般不需要改 |
| EquipmentMode | MinPieces | 默认炼器模式 |
| EquipmentTargetAttr | -1 | 成品法宝属性：-1 不指定 / 0 金 / 1 水 / 2 木 / 3 火 / 4 土 / 5 冰 / 6 风 / 7 雷 |
| EquipmentMaterialPolicy | MaxRepeatCount | 材料策略：MaxRepeatCount 最多炼制次数 / LowGradeFirst 低阶材料优先 |
| EquipmentWorkers | 0 | CP-SAT 搜索线程数：0 = 自动（按 CPU 核数，最多 16）；1 = 单线程（结果最稳定） |
| EquipmentDeterministic | false | 严格复现模式（仅调试）：锁单线程 + 固定种子 |
| **EquipmentDecomposedGate** | **true** | 覆盖门槛用「分解法」快速判定（可行的门槛通常几十毫秒命中）。关闭则全部回落到联合模型，会慢很多 |
| **EquipmentDecomposedMaterial** | **true** | 材料阶段用「分解法」（固定批次数二分 / 品阶秩加权）。关闭则回落到联合模型的整数乘法优化，会慢 50 倍左右 |

两个时间上限也能在窗口里按 −/+ 直接调。「最多成丹」只给一个方案，其余模式最多给 3 个。

## 原理

- 游戏规则（反编译所得）：阳格加属性、阴格减属性，加上丹炉/天赋的固定加成后，必须与丹方要求**完全相等**才出丹。
- 选材：按件数从少到多逐层搜索；同属性的材料归为一类；用单维可达性表和势函数下界剪枝。
- 装箱：异形块回溯（每次覆盖第一个空格或在预算内留空），先做棋盘与按行列模 k 染色快筛。
- 摆放：调用游戏自带的 `CraftingDrugCell.LoadCraftingTemplateSto`，与「配方」页一键摆放走同一逻辑。

## 炼器统一流程

选定符文后，窗口里设置三件事：**符文优先级**（可多选、可调顺序，勾选=优先组）、**成品属性**（不指定/金水木火土冰风雷）、**材料策略**（最多炼制次数 / 低阶材料优先），点「计算摆法」。

求解流程（详细性能分析与优化记录见提交历史）：

1. **覆盖门槛判定**：满级可行性先快速检查；满级不可行后按「覆盖数」逐层二分（`Σ hasL[r][l] >= H_l` 硬约束）。每个门槛**优先用分解法**判定 —— 枚举该门槛的最小等级向量 → 数量模型 → 阴阳两面装填 → 装不下就加「极小不可装核」形状排除约束再重解。可行的门槛通常 **13~199ms** 命中，明显不可行的门槛 **~0.5s** 证明；分解法未决则回落联合模型多种子求解（这是目前唯一的慢路径）。
2. **联合几何模型**：材料按「旋转等价形状」归类，位置变量按类型而不是逐材料枚举（189 种材料只有 17 类形状，位置变量 40418 → 3702），几何与数量在同一模型里求解。
3. **材料阶段优先用分解法**：质量锁定后，`最多炼制次数` 走「固定批次数 B 的二分 + 装填 + 形状切割」（纯线性、可证明最优），`低阶优先` 走「品阶秩加权目标」；实测材料阶段 **0.13~0.97 秒**（原联合模型整数乘法要 12 秒且证不出最优）。分解法结果更差或复核不过时回退联合模型。
4. 紧盘输入（有效材料 > 80 且形状类型 ≤ 32）自动把预算从 30 秒放宽到 45 秒。
5. 所有候选都通过独立复核（库存、越界、重叠、符文层数、成品属性）才展示；重复点「计算摆法」**每次都会重新求解**（不复用旧结果）。
6. 只有求解器明确返回 `Infeasible` 才剪枝；`Unknown`/超时一律保守处理，绝不当作不可行。

实测参考（鞋子2：5 符文、7×10 双盘、189 种材料、真实存档库存）：

| 版本 | 总耗时 | 材料阶段 | 等级9 命中 |
| --- | --- | --- | --- |
| 0.4.0 | 35~45 秒 | 12 秒 | 偶尔退到等级8 |
| **0.5.0** | **6.6~11.5 秒** | **0.13~0.97 秒** | **12/12** |

### 实验性方案（默认关闭，仅保留代码）

- **180° 对称破坏**：联合模型支持对任意矩形盘加「前一半至少占一格」的约束。离线多尺寸测试（3×3~10×10）表明它**反而更慢或质量下降**（5×5 慢 3.4 倍，7×7 从 Optimal 降为 Feasible，7×10 覆盖从 50301 退到 50300），因此默认关闭。
- **确定性复现**：`EquipmentDeterministic`（默认关）锁定单线程 + 固定种子，仅调试用。
- **固定批次数线性模型**：`batchesTarget` 参数（仅测试用）。A/B 显示乘法模型 1.7~2.2s 即证 Optimal，固定 B 二分 2.7~2.9s，故不采用。

## 构建

`lib/` 下放以下 dll（不随仓库分发）：游戏 `Zaohua_Data\Managed` 里的 `Assembly-CSharp`、`UnityEngine`、`UnityEngine.CoreModule`、`UnityEngine.IMGUIModule`、`UnityEngine.InputLegacyModule`、`UnityEngine.TextRenderingModule`、`UnityEngine.UI`，以及 `BepInEx\core` 里的 `BepInEx`、`0Harmony`。

```
dotnet build src -c Release
```

离线测试（需先用 [zaohua-guixu-shop 的 tools/extract.py](https://github.com/Jack-TJY/zaohua-guixu-shop) 解出配置表）：

```
dotnet run --project tests -c Release -- unpacked/data
```

环境变量可开关的专项测试：

| 变量 | 作用 |
| --- | --- |
| `UTEST=1` | 炼器统一流程验收用例（覆盖优先/逐层覆盖/部分激活/优先级/上限差异/共享需求/未激活负属性/并列归金等） |
| `P1FIX=1` | 早期缺陷回归 |
| `SHOE=1` | 鞋子2 配方复现（真实库存 + 7×10） |
| `GRIDSET=1` | 多尺寸盘对比测试集（3×3 / 4×4 / 5×5 / 5×8 / 7×7 / 7×10 / 9×10 / 10×10，对比有/无对称破坏） |

## 更新记录

### 0.5.0（2026-11-16）

**炼器速度大幅提升：鞋子2 从 35~45 秒降到 6.6~11.5 秒，等级9 稳定命中。**

- 新增**覆盖门槛分解法判定**（`EquipmentDecomposedGate`）：可行的门槛 13~199ms 命中（原 3.5~9 秒），明显不可行的门槛 ~0.5 秒证明（原 14 秒 Unknown）。
- 新增**材料阶段分解法**（`EquipmentDecomposedMaterial`）：`最多炼制次数` 用固定批次数二分得到**可证明的最优批次**，`低阶优先` 用品阶秩加权目标；材料阶段 12 秒 → 0.13~0.97 秒，且材料价格/批次/品阶与旧版完全一致。
- 覆盖门槛最小向量枚举改为「嵌套集合直接构造」，8 符文以上不再因组合爆炸放弃（鞋子3：20480 组合 → 精确 5 个最小向量）。
- CP-SAT 自动线程上限 8 → **16**（对照测试 16 线程命中率最高）。
- 覆盖门槛预算 14 → 20 秒，为游戏内 CPU 被渲染抢占的情况留余量。
- 材料阶段预算上限 12 秒（实测给满反而更差且拖长等待）。
- 修复**质量排序键**缺陷：`[1,1,2,2,2]` 与 `[1,1,1,2,3]` 曾被判为同质量，导致"省料"后处理把二层覆盖降级。
- 修复材料阶段目标错用：走覆盖前沿时曾误入质量分支，导致「材料」步骤从未真正优化材料。
- 重复点「计算摆法」改为**每次重新求解**，不再复用上次结果。
- **炼丹界面**：丹方按丹药属性分类筛选（18 类：气血上限/回血/速度/护甲/护罩/物攻/物防/术攻/术防/灵根/丹田/神魂/气运/寿元/骨龄/修炼/突破/辅助）、丹方名后显示耐药性、整体字号放大、新增搜索框。

### 0.4.0

- 炼器改为统一流程（符文优先级组 + 可选成品属性 + 材料策略），接入 CP-SAT 与联合几何模型。
