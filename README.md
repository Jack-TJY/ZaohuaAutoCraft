# 炼器炼丹小助手（ZaohuaAutoCraft）

《造化仙缘》的 BepInEx 插件。炼丹时选好丹方、炼器时选好符文，插件会算出材料怎么摆进阴阳两边的格子并替你摆上；**炼制/锻造按钮仍由你自己点**。

- 版本：**0.5.2**
- 依赖：BepInEx 5（x64）
- 求解器：CP-SAT（OR-Tools），并配合自研的分解法快速判定

---

## 功能一览

| | 炼丹 | 炼器 |
| --- | --- | --- |
| 快捷键 | `F9` 打开/关闭「自动炼丹」窗口 | `F9` 打开/关闭「自动炼器」窗口（同一个 `OpenKey`） |
| 前置 | 装备丹炉 | 装备锻造锤 + 在游戏原界面勾选符文 |
| 选择对象 | 丹方列表（可筛选/搜索） | 符文（可设优先级） |
| 输出 | 材料摆法 + 成丹数/品质预测 | 摆法 + 符文等级 + 可炼次数 |
| 摆放方式 | 点「摆上」自动摆入 | 点「摆上」自动摆入 |

> 两个窗口共用快捷键 `F9`：插件根据当前打开的是炼丹还是炼器界面，决定开关哪个窗口。两个界面右上角也都有一个「自动摆放」按钮可以直接点。

**炼丹模式（5 种）**

| 模式 | 说明 |
| --- | --- |
| 最少材料 | 达到丹方要求用的材料最少 |
| 最低品阶 | 优先用低品阶材料 |
| 最多成丹 | 成丹数量最多 |
| 最高品质 | 成丹品质最高 |
| 最多可炼次数 | 同一摆法可重复炼制的次数最多 |

**炼丹丹方筛选**

- 按丹药属性分类：气血上限 / 回血 / 速度 / 护甲 / 护罩 / 物攻 / 物防 / 术攻 / 术防 / 灵根 / 丹田 / 神魂 / 气运 / 寿元 / 骨龄 / 修炼 / 突破 / 辅助（共 18 类，自动从丹药效果推断）
- 丹方名后显示**耐药性**
- 支持关键词搜索

**炼器设置（三件事）**

| 设置 | 可选值 |
| --- | --- |
| 符文优先级 | 多选、可调顺序；勾选 = 优先组 |
| 成品属性 | 不指定 / 金 / 水 / 木 / 火 / 土 / 冰 / 风 / 雷 |
| 材料策略 | 最多炼制次数 / 低阶材料优先 |

## 安装

1. 游戏已装好 BepInEx 5（x64）。
2. 解压发布包 `ZaohuaAutoCraft-0.5.2.zip`，把里面的 **8 个 DLL 全部**放进 `游戏目录\BepInEx\plugins\`（不能只放 `ZaohuaAutoCraft.dll`）：

   | 文件 | 大小 | 说明 |
   | --- | --- | --- |
   | `ZaohuaAutoCraft.dll` | 0.2 MB | 插件本体 |
   | `Google.OrTools.dll` | 1.7 MB | CP-SAT 求解器托管包装 |
   | `Google.Protobuf.dll` | 0.5 MB | OR-Tools 依赖 |
   | `google-ortools-native.dll` | **21.2 MB** | CP-SAT 原生库（Windows x64）|
   | `System.Buffers.dll` | 27 KB | OR-Tools 依赖 |
   | `System.Memory.dll` | 145 KB | OR-Tools 依赖 |
   | `System.Numerics.Vectors.dll` | 113 KB | OR-Tools 依赖 |
   | `System.Runtime.CompilerServices.Unsafe.dll` | 23 KB | OR-Tools 依赖 |

3. 启动游戏，炼丹界面右上角会出现「自动摆放」按钮。
4. **更新插件后必须完全重启游戏**（BepInEx 只在启动时加载插件）。

> **关于 OR-Tools**：插件用 OR-Tools 的 CP-SAT 求解器，但它**不需要你另外安装**（不用装 Python、不用 pip、不用配置环境变量）。上面那 7 个 OR-Tools 相关 DLL 就是它的全部依赖，随发布包一起分发。少放任何一个都会在游戏日志里报 `FileNotFoundException` 或 `DllNotFoundException`，插件功能失效。
>
> 发布包约 **23.8 MB**，其中 21.2 MB 是 `google-ortools-native.dll`——这是正常的，OR-Tools 原生库本身就这么大。

## 使用

**炼丹**

1. 装备丹炉，打开炼丹界面，点「自动摆放」（或按 `F9`）。
2. 选丹方（默认只列已学和自己炼过的；勾「显示全部丹方」列出全部），可用属性分类筛选和搜索。
3. 点「计算摆法」，确认材料清单后点「摆上」。
4. 插件会读取游戏自己的结算结果核对丹方识别是否正确，然后由你点「炼制」。

**炼器**

1. 装备锻造锤，打开炼器界面。
2. 在游戏原界面勾选符文，按 `F9` 打开「自动炼器」窗口（与炼丹共用同一个快捷键）。
3. 设置符文优先级 / 成品属性 / 材料策略，点「计算摆法」。
4. 点「摆上」，然后由你点「锻造」。

> 重复点「计算摆法」**每次都会重新求解**，不会复用上一次结果。

## 配置

配置文件：`BepInEx\config\zaohua.autocraft.cfg`

### 通用

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `OpenKey` | `F9` | 打开/关闭「自动摆放」窗口（炼丹与炼器共用；不要设成 F5/F8，那是游戏快速存读档） |
| `ButtonX` / `ButtonY` | `-1` | 「自动摆放」按钮位置，拖动按钮会自动保存 |
| `TimeLimitMs` | `3000` | 炼丹最长计算时间（毫秒），用于最少材料/最低品阶/最多可炼次数/建议补料 |

### 炼丹

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `ShowAllRecipes` | `false` | 是否列出全部丹方 |
| `Mode` | `MinPieces` | 默认模式，窗口里切换会自动记住 |
| `PlacementTimeLimitMs` | `8000` | 最长计算时间（毫秒），用于最多成丹/最高品质；越长丹数/品质越高 |

### 炼器

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `EquipmentTimeLimitMs` | `3000` | 炼器最长计算时间（毫秒）。材料多/盘面紧时会自动放宽，一般不需要改 |
| `EquipmentMode` | `MinPieces` | 默认炼器模式。**注意：0.5.0 统一流程下此项不生效**（实际由窗口的符文优先级/成品属性/材料策略决定），仅为兼容旧配置保留 |
| `EquipmentTargetAttr` | `-1` | 成品法宝属性：`-1` 不指定 / `0` 金 / `1` 水 / `2` 木 / `3` 火 / `4` 土 / `5` 冰 / `6` 风 / `7` 雷 |
| `EquipmentMaterialPolicy` | `MaxRepeatCount` | 材料策略：`MaxRepeatCount` 最多炼制次数 / `LowGradeFirst` 低阶材料优先 |
| `EquipmentWorkers` | `0` | CP-SAT 搜索线程数：`0` = 自动（按 CPU 核数，最多 16）；`1` = 单线程（结果最稳定） |
| `EquipmentDeterministic` | `false` | 严格复现模式（仅调试）：锁单线程 + 固定种子 |
| `EquipmentDecomposedGate` | `true` | 覆盖门槛用分解法快速判定。关闭后全部回落联合模型，会慢很多 |
| `EquipmentDecomposedMaterial` | `true` | 材料阶段用分解法（固定批次数二分 / 品阶秩加权）。关闭后回落整数乘法优化，约慢 50 倍 |

时间上限也能在窗口里按 `−` / `+` 直接调。「最多成丹」只给一个方案，其余模式最多给 3 个。

## 原理

### 游戏规则（反编译所得）

- **炼丹**：阳格加属性、阴格减属性，加上丹炉/天赋的固定加成后，必须与丹方要求**完全相等**才出丹。
- **炼器**：阴阳两盘分别提供正/负属性，符文逐层解锁需要满足该层的属性门槛。

### 炼丹算法

- 选材：按件数从少到多逐层搜索；同属性材料归为一类；用单维可达性表和势函数下界剪枝。
- 装箱：异形块回溯（每次覆盖第一个空格或在预算内留空），先做棋盘与按行列模 k 染色快筛。
- 摆放：调用游戏自带的 `CraftingDrugCell.LoadCraftingTemplateSto`，与「配方」页一键摆放走同一逻辑。

### 炼器算法

求解分两个阶段，每个阶段都**优先用分解法**，失败才回落联合模型：

**① 覆盖门槛判定**

1. 先快速检查满级可行性（通常 1-2 秒出结论）。
2. 满级不可行后按「覆盖数」逐层二分（`Σ hasL[r][l] >= H_l` 硬约束）。
3. 每个门槛优先用**分解法**：
   - 枚举该门槛的最小等级向量（嵌套集合直接构造，8 符文以上也不会组合爆炸）
   - 数量模型（属性阈值 + 库存 + 面积）
   - 阴阳两面分别装填
   - 装不下的形状集合生成「极小不可装核」排除约束，重解
4. 可行的门槛通常 **13-199 毫秒**命中；明显不可行的门槛 **-0.5 秒**完成证明。
5. 分解法未决（Unknown/超时）才回落**联合几何模型**：材料按「旋转等价形状」归类，位置变量按类型而非逐材料枚举（189 种材料只有 17 类形状，位置变量 40418 → 3702）。这是目前唯一的慢路径。

**② 材料阶段**

质量锁定后按策略分支：

| 策略 | 分解法做法 | 耗时 |
| --- | --- | --- |
| 最多炼制次数 | 二分批次数 B，每个 B 是纯线性数量模型（`usage_i ≤ floor(stock_i/B)`）→ 装填 → 形状切割 → 证明最大可行 B | -0.2 秒 |
| 低阶材料优先 | 单次求解，目标 = 最小化品阶秩加权和，其次件数、再次价格 | 0.7-1.0 秒 |

分解法结果更差或复核不通过时回退联合模型（整数乘法优化，约 12 秒且证不出最优）。

**③ 安全约束**

- 只有求解器明确返回 `Infeasible` 才剪枝；`Unknown` / 超时一律保守处理，**绝不当作不可行**。
- 所有候选都通过独立复核（库存、越界、重叠、符文层数、成品属性）才展示。

## 性能

实测对象：**7×10 阴阳双盘 + 5 符文配方**（189 种材料、真实存档库存）。
符文配置：ID `196/249/252/258/261`，上限 `[1,1,3,3,3]`，逐层需求分别为
`冰+100 风+100 雷+100` / `水+10000 风+1000` / `土+8000 火+4000` / `木+2000 雷+1000` / `水+2000 冰+1000`。

| 版本 | 总耗时 | 材料阶段 | 等级 9 命中 |
| --- | --- | --- | --- |
| 0.4.0 | 35-45 秒 | 12 秒 | 偶尔退到等级 8 |
| **0.5.0** | **6.6-11.5 秒** | **0.13-0.97 秒** | **12/12** |

其他实测结论：

- CPU 线程数：8 / 16 / 24 对照，**16 线程最优**（24 线程不更优且更耗 CPU）。
- 并行策略：串行换种子 + 每次 16 线程，优于「多种子并行 + 每次都 4 线程」（后者 0/5 命中）。
- **8 符文配方**（上限 `[1,4,3,3,3,3,1,3]`）：覆盖前沿 14-15 次检查，总耗时约 35-45 秒。

## 更新记录

### 0.5.2

**项目改名：自动炼丹炼器 → 炼器炼丹小助手。**

- 插件显示名改为「炼器炼丹小助手」（游戏日志、BepInEx 插件列表、窗口按钮提示都会显示新名字）。
- 保持不变（为兼容旧安装）：程序集名 `ZaohuaAutoCraft.dll`、插件 GUID `zaohua.autocraft`、配置文件名 `zaohua.autocraft.cfg`、窗口标题「自动炼丹」/「自动炼器」。

### 0.5.1（2026-11-16）

**发布包补全 + 清理死代码。**

- 修复**发布包不完整**：原发布只含 `ZaohuaAutoCraft.dll`，缺少 OR-Tools 的 7 个依赖（含 21.2 MB 的 `google-ortools-native.dll`）。缺少时插件会在加载阶段报 `FileNotFoundException` / `DllNotFoundException`。现在 csproj 增加了 `CopyOrToolsNative` MSBuild 目标，构建时自动复制原生库，发布包为 8 个文件的 zip（约 10.3 MB 压缩 / 23.8 MB 解压）。
- 清理炼器窗口死代码：删除从未被渲染引用的 `ModeNames`/`ModeValues`（旧模式按钮残留声明）。
- 修复失效的属性核对分支：原判断 `request.Mode == EquipmentMode.MaxAttr` 因 `Mode` 从未被赋值而永不执行，改为 `request.TargetAttr >= 0`。
- README 安装章节列出全部 8 个必需文件并说明 OR-Tools 无需另外安装。

### 0.5.0（2026-11-16）

**炼器速度大幅提升：5 符文配方从 35-45 秒降到 6.6-11.5 秒，等级 9 稳定命中。**

性能

- 新增**覆盖门槛分解法判定**（`EquipmentDecomposedGate`）：可行门槛 13-199ms 命中（原 3.5-9 秒），明显不可行门槛 -0.5 秒证明（原 14 秒 Unknown）。
- 新增**材料阶段分解法**（`EquipmentDecomposedMaterial`）：材料阶段 12 秒 → 0.13-0.97 秒，材料价格/批次/品阶与旧版完全一致。
- CP-SAT 自动线程上限 8 → **16**（对照测试 16 线程命中率最高）。
- 覆盖门槛预算 14 → 20 秒，为游戏内 CPU 争用留余量。
- 材料阶段预算上限 12 秒。

修复

- 覆盖门槛最小向量枚举改为「嵌套集合直接构造」：8 符文以上不再因组合爆炸放弃（8 符文配方：20480 组合 → 精确 5 个最小向量）。
- 修复**质量排序键**缺陷：`[1,1,2,2,2]` 与 `[1,1,1,2,3]` 曾被判为同质量，导致「省料」后处理把二层覆盖降级。
- 修复材料阶段目标错用：走覆盖前沿时曾误入质量分支，导致「材料」步骤从未真正优化材料。
- 修复覆盖前沿 `Unknown` 处理：不再直接跳出整层，改为继续向低值找见证解并标记未证最优。
- **炼丹界面**：丹方按丹药属性分类筛选（18 类）、丹方名后显示耐药性、整体字号放大、新增搜索框。

行为变更

- 重复点「计算摆法」改为**每次重新求解**，不再复用上次结果。

### 0.4.0

- 炼器改为统一流程（符文优先级组 + 可选成品属性 + 材料策略），接入 CP-SAT 与联合几何模型。
